5. Zenoh Middleware¶

當 ROS 2 節點需要跨機器、跨子網或無線環境通訊時，預設的 DDS 常因多播（multicast）限制而難以運作。
本教學介紹以 Zenoh 作為 ROS 2 中介層（Middleware）的設定方式，協助團隊在多機器人場景下建立穩定的通訊。

推薦資源

更完整的 Zenoh 與 rmw_zenoh 背景說明，可參考 rmw_zenoh 基本介紹。

1. 背景¶

1-1. 為何需要 Zenoh？¶

ROS 2 預設使用 DDS 作為中介層，在區域網路內運作良好，但在以下場景常遇到問題：

  • 無線網路品質不穩，DDS 的 discovery 封包過多
  • 工廠或 private 5G 環境不支援多播
  • 需要跨子網、從地端機器人連到雲端或遠端工作站
  • 多台機器人同時運行，topic 命名容易衝突

經 ROS 2 社群評估，Zenoh 被選為第一個非 DDS 的官方 RMW 實作（rmw_zenoh）。
從 ROS 2 Kilted 起為 Tier 1 支援，並 backport 至 Humble 等仍在維護的版本。

項目 DDS（預設 RMW） rmw_zenoh
節點發現 多播為主，跨網段困難 集中式 Router + gossip，可跨網段
無線環境 易因 discovery 封包過多而不穩 針對無線與 WAN 優化
跨網通訊 需額外設定或 VPN 原生支援 Router 橋接
切換成本 — 需安裝套件、啟動 Router、設定環境變數

1-2. rmw_zenoh 架構概覽¶

rmw_zenoh 在每台機器上預設運行一個 Zenoh Router（rmw_zenohd），負責：

  1. 協助本機 ROS 2 節點互相發現
  2. 對外連線時充當 Gateway，轉發訊息

本機節點（Publisher / Subscriber）透過 Router 完成 discovery 後，資料傳輸可走點對點（P2P）直連，減少 Router 負擔。

與 ROS 1 的差異

雖然 Router 看起來像 ROS 1 的 roscore，但 rmw_zenohd 可隨時重啟，不會導致所有節點必須重新啟動。

2. 使用 rmw_zenoh 還是 zenoh_bridge_ros2dds？¶

若團隊已有以 DDS 運行的 ROS 2 系統，不想全面更換 RMW，可使用 zenoh-bridge-ros2dds 在 ROS 2 與 Zenoh 之間做協定轉換。

項目 rmw_zenoh zenoh-bridge-ros2dds
定位 取代 ROS 2 的 RMW 層 在既有 DDS 系統外掛橋接
效能 較佳，無 DDS ↔ Zenoh 轉換開銷 每次轉換需複製訊息，開銷較大
對既有系統影響 需設定 RMW_IMPLEMENTATION 不動 RMW，只跑 bridge 程序
典型用途 新專案、全面導入 Zenoh 評估 Zenoh、漸進式導入、跨 Domain 橋接
Service / Action 完整支援 FastDDS 環境下 service / action 支援有限
互操作性 與 bridge 不相容（key expression 不同） 與 rmw_zenoh 不相容

選擇建議

  • 新專案或願意全面切換：優先使用 rmw_zenoh。
  • 既有系統、只想試用或部分橋接：先用 zenoh-bridge-ros2dds 評估，確認需求後再考慮遷移。
  • 同一套 ROS 2 通訊網路內，不可混用 rmw_zenoh 與 zenoh-bridge-ros2dds 互通。

3. 設定步驟¶

前置條件

以下假設兩台機器已能互相 ping 通（例如同一 Wi-Fi，或透過 4. ETH over SSH 以乙太網路直連）。
兩台機器須使用相同的 ROS Distro 與 ROS Domain ID。

機器 角色（範例） IP
Host A 機器人 / 地端 192.168.0.50
Host B 工作站 / 遠端 192.168.50.100

Distro 相容性

Humble 與 Iron 以後的 distro 在 type hash 上不相容，不同 ROS 版本之間無法透過 rmw_zenoh 通訊。
跨機設定時，兩端必須是相同的 ROS Distro（例如都是 Humble）。

3-1. 安裝¶

在兩台機器的 ROS 2 環境中安裝 rmw_zenoh：

sudo apt update
sudo apt install ros-${ROS_DISTRO}-rmw-zenoh-cpp

若需最新功能，可從原始碼編譯，詳見 rmw_zenoh。

安裝完成後，確認套件存在：

ros2 pkg list | grep rmw_zenoh

3-2. 設定 bashrc¶

在兩台機器的 ~/.bashrc 加入以下環境變數，使每次開啟 terminal 自動使用 rmw_zenoh：

# 指定 ROS 2 使用 rmw_zenoh
export RMW_IMPLEMENTATION=rmw_zenoh_cpp

# 同一 ROS 網域內的所有機器設定相同 Domain ID 
export ROS_DOMAIN_ID=20

修改後重新載入：

source ~/.bashrc

Zenoh Router 是否寫進 bashrc？

rmw_zenohd 建議以 systemd service 或 launch 檔在開機時啟動，而非直接寫在 bashrc（避免每開一個 terminal 就啟動一個 Router）。
開發測試階段可手動在獨立 terminal 執行 ros2 run rmw_zenoh_cpp rmw_zenohd。

3-3. 本機驗證（單機）¶

在正式跨機設定前，先確認本機 talker / listener 正常：

ros2 run rmw_zenoh_cpp rmw_zenohd

export RMW_IMPLEMENTATION=rmw_zenoh_cpp
ros2 run demo_nodes_cpp talker

export RMW_IMPLEMENTATION=rmw_zenoh_cpp
ros2 run demo_nodes_cpp listener

Listener 應持續收到 /chatter 訊息。

Checkpoint

  1. 本機 talker / listener 能正常通訊。
  2. echo $RMW_IMPLEMENTATION 輸出 rmw_zenoh_cpp。

3-4. Router-to-Router（雙機對等連線）¶

適用於兩台機器各自有 ROS 2 節點，且兩邊都需要獨立的 Zenoh Router。
兩台 Router 互相連線後，兩端的 ROS 2 節點即可跨機發現與通訊。

拓撲示意：

Host A (192.168.0.50)                    Host B (192.168.50.100)
┌─────────────────────┐                ┌─────────────────────┐
│  rmw_zenohd :7447   │◄──────────────►│  rmw_zenohd :7447   │
│  ROS 2 nodes        │   tcp/7447     │  ROS 2 nodes        │
└─────────────────────┘                └─────────────────────┘

Host A（192.168.0.50）— 先啟動 Router：

ros2 run rmw_zenoh_cpp rmw_zenohd

ros2 run demo_nodes_cpp talker

Host B（192.168.50.100）— Router 連線至 Host A：

export ZENOH_CONFIG_OVERRIDE='connect/endpoints=["tcp/192.168.0.50:7447"]'
ros2 run rmw_zenoh_cpp rmw_zenohd

ros2 run demo_nodes_cpp listener

Host B 的 listener 應能收到 Host A talker 發佈的 /chatter 訊息。

使用設定檔取代環境變數

若需長期固定設定，可複製預設 Router 設定檔並修改 connect 區塊：

{
  connect: {
    endpoints: ["tcp/192.168.0.50:7447"],
  },
}

啟動 Router 前指定路徑：

export ZENOH_ROUTER_CONFIG_URI=$HOME/my_zenoh_router_config.json5
ros2 run rmw_zenoh_cpp rmw_zenohd

防火牆

確保 TCP port 7447 在兩台機器之間可互通。
可用 nc -zv 192.168.0.50 7447 從 Host B 測試 Host A 的 Router 是否在監聽。

Checkpoint

  1. Host A 跑 talker、Host B 跑 listener，跨機收到 /chatter。
  2. 兩端 ros2 topic list 能看到相同的 topic。
  3. 兩端 echo $ROS_DOMAIN_ID 一致。

3-5. Router-to-Client（遠端 Client 連至機器人 Router）¶

適用於一邊是機器人（跑 Router + 節點），另一邊是遠端監控端（如 RViz、筆電），只需連到機器人的 Router，無需在遠端再跑一個 Router。

此模式下，遠端節點以 Client mode 連線，由機器人端的 Router 負責轉發訊息。

拓撲示意：

Host A (192.168.0.50) — 機器人              Host B (192.168.50.100) — 遠端
┌─────────────────────────┐                ┌─────────────────────────┐
│  rmw_zenohd :7447        │◄───────────────│  ROS 2 nodes (client)   │
│  ROS 2 nodes            │   tcp/7447     │  不啟動 rmw_zenohd       │
└─────────────────────────┘                └─────────────────────────┘

Host A（192.168.0.50）— 機器人端：

ros2 run rmw_zenoh_cpp rmw_zenohd

ros2 run demo_nodes_cpp talker

Host B（192.168.50.100）— 遠端 Client：

在 ~/.bashrc 或執行前設定 Client 連線（不需要啟動 rmw_zenohd）：

export RMW_IMPLEMENTATION=rmw_zenoh_cpp
export ZENOH_CONFIG_OVERRIDE='mode="client";connect/endpoints=["tcp/192.168.0.50:7447"]'

ros2 run demo_nodes_cpp listener

Router-to-Router vs. Router-to-Client

模式 遠端是否跑 Router 適用情境
Router-to-Router 是 雙向對等、多機器人協作、兩邊都有大量節點
Router-to-Client 否 遠端監控、RViz、偶爾連線的筆電

遠端只有少量節點時，Router-to-Client 較省資源且設定較簡單。

Checkpoint

  1. Host B 不啟動 rmw_zenohd，僅以 client 模式連線，仍能收到 Host A 的 topic。
  2. 在 Host B 執行 ros2 topic echo /chatter，確認資料正常。
  3. 斷開 Host B 的網路後重新連線，節點能自動恢復（Zenoh 支援 Router 晚於節點啟動後自動連線）。

4. 常見問題¶

4-1. IPv4-only 系統 Router 崩潰¶

預設 Router 設定可能監聽 IPv6 [::]:7447，在 IPv6 未啟用的系統會導致 Router 無法啟動。
可改用 IPv4 監聽：

export ZENOH_CONFIG_OVERRIDE='listen/endpoints=["tcp/0.0.0.0:7447"]'
ros2 run rmw_zenoh_cpp rmw_zenohd

4-2. 切換 RMW 後 CLI 異常¶

若先前用其他 RMW 啟動過 ROS 2 daemon，切換至 rmw_zenoh 後 ros2 node list 等指令可能顯示錯誤資訊。
先停止 daemon 再重試：

pkill -9 -f ros && ros2 daemon stop

4-3. Docker 環境注意事項¶

若 ROS 2 跑在 Docker 內，須確保：

  • Container 能存取 host 網路，或正確映射 port 7447
  • 跨 container 使用 Zenoh Shared Memory 時，需設定 /dev/shm（詳見 rmw_zenoh）
  • 每個 container 內的 RMW_IMPLEMENTATION、ROS_DOMAIN_ID、ZENOH_CONFIG_OVERRIDE 須一致

4-4. 除錯用環境變數¶

環境變數 說明
RUST_LOG=zenoh=info 顯示 Zenoh 初始化與監聽 endpoint
ZENOH_ROUTER_CHECK_ATTEMPTS=0 節點無限期等待 Router 連線（適合 Router 晚啟動）
ZENOH_ROUTER_CHECK_ATTEMPTS=-1 跳過 Router 檢查（本機測試用）
